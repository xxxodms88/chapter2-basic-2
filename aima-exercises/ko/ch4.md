## 4.1
### 번역
다음 각 특수한 경우로부터 나오는 알고리즘의 이름을 말하시오.
1. $k = 1$인 국소 빔 탐색(local beam search)
2. 초기 상태가 하나이고 유지하는 상태 수에 제한이 없는 국소 빔 탐색
3. 항상 $T = 0$인 담금질 기법(simulated annealing) (종료 검사는 생략)
4. 항상 $T=\infty$인 담금질 기법
5. 개체군 크기가 $N = 1$인 유전 알고리즘

### 풀이
1. **언덕 오르기(hill climbing)**. 상태 하나만 유지하면서 후속자 중 가장 좋은 것으로 옮겨 가므로 가파른 상승 언덕 오르기와 같다.
2. **너비 우선 탐색(breadth-first search)**. 매 단계 현재 상태들의 모든 후속자를 버리지 않고 다음 단계로 넘기므로, 깊이 1, 2, 3, …의 상태 전체를 차례로 펼치는 것과 같다.
3. **1차 선택 언덕 오르기(first-choice hill climbing)**. $T=0$이면 나빠지는 이동의 수락 확률 $e^{\Delta E/T}$가 0이 되어, 무작위로 고른 후속자가 더 좋을 때만 이동한다. 종료 검사를 빼면 지역 최댓값에서 계속 머문다.
4. **무작위 보행(random walk)**. $T=\infty$이면 $e^{\Delta E/T} = 1$이라 무작위로 고른 후속자를 좋든 나쁘든 항상 받아들인다.
5. **무작위 보행**(변이만 하는 탐색). 개체가 하나뿐이면 선택은 항상 그 개체를 두 번 고르고, 자기 자신과의 교차는 자기 자신을 낳는다. 남는 것은 변이뿐이라 상태를 무작위로 조금씩 바꾸는 탐색이 된다.

## 4.2
### 번역
[연습문제 3.19]에서는 조각들이 여유 없이 정확히 맞물린다는 가정 아래 기차 선로를 만드는 문제를 다루었다. 이제 실제 문제, 즉 조각들이 정확히 맞물리지 않고 “올바른” 정렬에서 양쪽으로 최대 10도까지 회전할 수 있는 경우를 생각하자. 담금질 기법으로 풀 수 있도록 이 문제를 정식화하는 방법을 설명하시오.

### 풀이
담금질 기법은 **완전한 배치** 하나를 상태로 두고 조금씩 바꿔 가며 목적 함수를 줄이는 방식이므로, 다음처럼 정식화한다.

- **상태**: 모든 조각을 사용한 완전한 배치. 조각의 연결 순서(어느 조각이 어느 연결부에 붙는지)와 각 이음매의 회전 각도 $\theta_i \in [-10°, +10°]$.
- **목적 함수(에너지)** $E$: 최소화할 값.
  - 느슨한 끝 사이의 거리와 방향 차이의 합(끝이 서로 만나야 닫힌 선로가 됨),
  - 조각끼리 겹치는 면적(또는 겹치는 쌍의 수)에 큰 가중치,
  - 필요하면 이음매 각도를 크게 쓰는 데 대한 작은 벌점.
  - $E = 0$이면 겹침 없고 느슨한 끝 없는 선로다.
- **이웃 상태(이동)**:
  - 이음매 하나의 각도를 작은 양만큼 바꾸기(연속 변수),
  - 두 조각의 위치 맞바꾸기, 곡선 조각 뒤집기,
  - 조각 하나를 떼어 다른 열린 연결부에 붙이기.
- **스케줄**: 처음에는 높은 온도로 배치를 크게 바꾸는 이동도 받아들이고, 온도를 서서히 낮추면서 각도 미세 조정 위주로 수렴시킨다.

정확히 맞물리는 경우와 달리 각도가 연속이라 이산 탐색으로는 다루기 어렵지만, 담금질 기법은 연속 변수와 이산 변수를 섞은 상태에서도 그대로 쓸 수 있다.

## 4.3
### 번역
이 연습문제에서는 [연습문제 3.38]에서 정의한 유형의 TSP를 국소 탐색 방법으로 푸는 것을 살펴본다.
1. TSP를 푸는 언덕 오르기 방법을 구현하고 시험하시오. 그 결과를 MST 휴리스틱을 쓰는 A* 알고리즘으로 얻은 최적 해([연습문제 3.38])와 비교하시오.
2. 언덕 오르기 대신 유전 알고리즘을 써서 (a)를 반복하시오. 표현 방법에 대해서는 [Larrañaga 외, 1999]를 참고하면 좋다.

### 풀이
**1. 언덕 오르기**
- 상태: 도시를 한 번씩 방문하는 순회(순열). 목적: 순회 길이 최소화.
- 이웃: **2-opt** 이동. 순회에서 간선 두 개를 끊고 그 사이 구간을 뒤집어 다시 잇는다. 길이가 줄어드는 2-opt 이동이 없을 때까지 반복.

```python
def two_opt(d, tour):
    n = len(tour); improved = True
    while improved:
        improved = False
        for i in range(n - 1):
            for j in range(i + 2, n if i > 0 else n - 1):
                a, b, c, e = tour[i], tour[i + 1], tour[j], tour[(j + 1) % n]
                if d[a][c] + d[b][e] < d[a][b] + d[c][e]:
                    tour[i + 1:j + 1] = reversed(tour[i + 1:j + 1]); improved = True
    return tour
```

**2. 유전 알고리즘**
- 표현: 순열(경로 표현). 일반적인 한 점 교차는 도시가 중복되거나 빠지므로 쓸 수 없고, **순서 교차(OX)** 를 쓴다. 부모 1의 구간을 그대로 복사하고 나머지 칸은 부모 2에 나오는 순서대로 채운다.
- 변이: 구간 뒤집기(2-opt 한 번과 같음) 또는 두 도시 맞바꾸기.
- 선택: 짧은 순회 상위 20%를 부모로 쓰는 엘리트 선택.

**실험 결과** (단위 정사각형 무작위 도시, 크기마다 20개 인스턴스. 최적 해는 A* + MST와 같은 값을 주는 동적 계획법(Held–Karp)으로 구함. 값은 최적 길이 대비 비율)

| 도시 수 | 2-opt 언덕 오르기 1회 | 2-opt 10회 무작위 재시작 | 유전 알고리즘 (개체 100, 300세대) |
|---|---|---|---|
| 8 | 평균 1.015, 최적 15/20 | 평균 1.000, 최적 20/20 | 평균 1.000, 최적 20/20 |
| 10 | 평균 1.012, 최적 13/20 | 평균 1.000, 최적 19/20 | 평균 1.001, 최적 18/20 |
| 12 | 평균 1.024, 최적 10/20 | 평균 1.000, 최적 20/20 | 평균 1.012, 최적 15/20 |

**해석**: 2-opt 언덕 오르기는 한 번만 돌려도 최적보다 평균 1~3% 정도만 길고, 무작위 재시작 10번이면 거의 항상 최적에 도달한다. 유전 알고리즘도 좋은 해를 찾지만, 같은 계산량이면 2-opt 재시작보다 나을 게 없었다. 도시 수가 늘면 A*는 상태 수 $n \cdot 2^n$ 때문에 곧 불가능해지지만, 국소 탐색은 수백~수천 개 도시에서도 빠르게 근사 해를 낸다. 이것이 국소 탐색의 장점이다.

## 4.5
### 번역
[그림: and-or-graph-search-algorithm]의 AND-OR-GRAPH-SEARCH 알고리즘은 뿌리에서 현재 상태까지의 경로 위에서만 반복 상태를 검사한다. 여기에 더해, 알고리즘이 방문한 모든 상태를 저장하고 그 목록과 대조한다고 하자. ([교재: breadth-first-search-algorithm]의 예를 보라.) 무엇을 저장해야 하는지, 그리고 반복 상태를 발견했을 때 알고리즘이 그 정보를 어떻게 써야 하는지 정하시오. (*힌트*: 적어도 이전에 성공적인 부분 계획이 만들어진 상태와 부분 계획을 찾지 못한 상태는 구분해야 한다.) [교재: cyclic-plan-section]에서 정의한 레이블을 사용해 부분 계획의 사본이 여러 개 생기지 않게 하는 방법을 설명하시오.

### 풀이
**저장할 정보**: 방문한 상태마다 다음 중 하나를 기록하는 표 `memo[state]`.
- **성공**: 그 상태에서 목표에 도달하는 부분 계획을 찾았음. 부분 계획(또는 그것을 가리키는 레이블)을 함께 저장.
- **실패**: 그 상태에서는 어떤 경로 조건과도 무관하게 계획이 없음이 확인됨.
- **조건부 실패**: 경로 위 반복(조상 상태로 돌아가는 순환) 때문에만 실패한 경우. 이 실패는 *그 경로 맥락*에 의존한다. 다른 경로로 이 상태에 오면 같은 조상이 경로에 없어서 성공할 수 있다. 따라서 이 경우는 확정 실패로 저장하면 안 된다(저장하지 않거나, 의존하는 조상 집합과 함께 저장).

**사용 방법**: OR-SEARCH가 상태 $s$를 만나면 먼저 `memo`를 본다.
- 성공으로 기록되어 있으면 탐색하지 않고 저장된 부분 계획을 돌려준다.
- 확정 실패로 기록되어 있으면 즉시 실패를 돌려준다.
- 기록이 없거나 조건부 실패면 평소처럼 탐색하고, 결과를 기록한다(실패가 경로 위 순환 검사에서 비롯되었는지 추적해야 한다).

**레이블로 사본 피하기**: 성공한 상태의 부분 계획에 레이블 $L_s$를 붙여 한 번만 저장한다. 같은 상태에 다른 경로로 다시 도달하면 부분 계획을 복사해 넣지 않고 “$L_s$로 가라(goto $L_s$)”는 참조만 넣는다. 그러면 계획은 트리가 아니라 공유 부분을 가진 DAG가 되고, 크기가 상태 수에 비례하는 수준으로 줄어든다.

## 4.6
### 번역
비순환 계획이 없을 때 순환 계획을 생성하도록 AND-OR-GRAPH-SEARCH 알고리즘을 수정하는 방법을 정확히 설명하시오. 세 가지 문제를 다뤄야 한다. 순환 계획이 앞부분을 다시 가리킬 수 있도록 계획 단계에 레이블을 붙이는 것, 순환 계획을 찾은 뒤에도 비순환 계획을 계속 찾도록 OR-SEARCH를 수정하는 것, 계획이 순환적인지 나타내도록 계획 표현을 확장하는 것이다. 여러분의 알고리즘이 (a) 미끄러운 진공청소기 세계, (b) 미끄럽고 변덕스러운 진공청소기 세계에서 어떻게 동작하는지 보이시오. 컴퓨터 구현으로 결과를 확인해 보아도 좋다.

### 풀이
**수정 사항**
1. **레이블**: OR-SEARCH가 상태 $s$를 처음 펼칠 때 그 계획 시작점에 레이블 $L_s$를 붙인다.
2. **경로 위 반복 처리**: 원래는 $s$가 경로 위에 있으면 실패를 돌려준다. 수정본은 대신 **순환 계획** “goto $L_s$”를 돌려주고, 이 결과에 *순환 표시*를 단다.
3. **계획 표현**: 반환값을 (계획, 순환 여부) 쌍으로 만든다. AND-SEARCH는 모든 결과 상태의 부분 계획을 합치면서, 하나라도 순환이면 전체를 순환으로 표시한다. 단, AND 노드의 결과가 **모두** 순환 참조뿐이면 목표로 빠져나갈 길이 없으므로 실패로 처리한다(적어도 한 갈래는 목표로 가야 함).
4. **OR-SEARCH의 선택**: 행동들을 차례로 시도하며 비순환 계획이 나오면 즉시 반환한다. 순환 계획만 나오면 그것을 후보로 기억해 두고 남은 행동을 계속 시도한다. 끝까지 비순환 계획이 없으면 기억해 둔 순환 계획을 반환한다.

**(a) 미끄러운 진공청소기 세계** (이동이 실패해 제자리에 머물 수 있음. Suck은 결정적)
상태 1에서:
```text
[Suck,
 L1: Right,
     if State = 5 then L1      // 미끄러져 왼쪽에 그대로 있음 → 다시 시도
     else Suck]                // 오른쪽에 도착(상태 6) → 청소하면 상태 8
```
Right를 성공할 때까지 반복하는 순환 계획이다. 비순환 계획은 존재하지 않는다(몇 번 시도하든 계속 미끄러질 수 있으므로).

**(b) 미끄럽고 변덕스러운 진공청소기 세계** (이동이 미끄러질 수 있고, Suck이 이웃 칸까지 청소하기도 하고 깨끗한 칸에 먼지를 떨어뜨리기도 함)
상태 1에서:
```text
[Suck,
 if State = 7 then []                       // 이웃 칸까지 청소됨 → 목표
 else L1: Right,                            // 상태 5
          if State = 5 then L1
          else Suck]                        // 상태 6 → 8
```
상태 7, 8이 아닌 다른 시작 상태에서도 같은 방식으로 “목표가 아니면 Suck, 이동이 실패하면 다시 시도” 구조의 순환 계획이 나온다. 깨끗한 칸에서 Suck하면 먼지가 생길 수 있으므로 계획은 깨끗한 칸에서 Suck하지 않는다.

## 4.7
### 번역
[교재: conformant-section]에서 우리는 센서 없는 탐색 문제를 풀기 위해 신뢰 상태(belief state)를 도입했다. 행동 열이 초기 신뢰 상태 $b$의 모든 물리 상태를 목표 상태로 옮기면 그 행동 열은 센서 없는 문제를 푼다. 에이전트가 $b$ 안의 모든 상태 $s$에 대해, 완전 관측 문제에서 물리 상태 $s$를 푸는 실제 최적 비용 $h^\*(s)$를 안다고 하자. 이 비용들을 이용해 센서 없는 문제에 대한 허용 가능한 휴리스틱 $h(b)$를 찾고, 허용 가능함을 증명하시오. [그림: vacuum2-sets-figure]의 센서 없는 진공청소기 문제에서 이 휴리스틱의 정확도에 대해 논평하시오. A*는 얼마나 잘 동작하는가?

### 풀이
**휴리스틱**: $h(b) = \max_{s \in b} h^*(s)$.

**허용 가능성 증명**: 행동 열 $P$가 신뢰 상태 $b$의 해라면, $P$는 $b$ 안의 모든 물리 상태 $s$를 목표로 옮긴다. 즉 $P$는 각 $s$에 대한 완전 관측 문제의 해이기도 하다(관측을 쓰지 않는 해일 뿐). 따라서 모든 $s \in b$에 대해 $\text{cost}(P) \ge h^*(s)$이고, 최적 해 $P^*$에 대해서도 $\text{cost}(P^*) \ge \max_{s\in b} h^*(s) = h(b)$. 그러므로 $h$는 과대평가하지 않는다. ($\min$이나 평균도 허용 가능하지만 $\max$가 가장 크므로 가장 정확하다.)

**센서 없는 진공청소기에서의 정확도**: 초기 신뢰 상태 $\{1,\dots,8\}$에서
- $h^*(1) = h^*(2) = 3$ (Suck, 이동, Suck), $h^*(3)=h^*(6)=1$, $h^*(4)=h^*(5)=2$, $h^*(7)=h^*(8)=0$이므로 $h(b) = 3$.
- 실제 최적 해는 [Right, Suck, Left, Suck] 같은 **4단계**이다. 휴리스틱은 3으로 1만큼 작다.

이처럼 오차가 작고, 그림의 도달 가능한 신뢰 상태도 12개뿐이라 A*는 매우 적은 노드만 확장하고 바로 최적 해를 찾는다. 일반적으로는 신뢰 상태가 클수록 “모든 상태를 동시에 해결해야 하는” 추가 비용을 $\max$가 반영하지 못해 휴리스틱이 덜 정확해진다.

## 4.8
### 번역
이 연습문제는 센서 없는 환경이나 부분 관측 환경에서 신뢰 상태 사이의 부분집합–상위집합 관계를 탐구한다.
1. 어떤 행동 열이 신뢰 상태 $b$의 해이면, $b$의 모든 부분집합에 대해서도 해임을 증명하시오. $b$의 상위집합에 대해서는 무엇을 말할 수 있는가?
2. (a)의 답을 활용하도록 센서 없는 문제를 위한 그래프 탐색을 어떻게 수정할지 자세히 설명하시오.
3. 부분 관측 문제를 위한 AND–OR 탐색을 (b)에서 설명한 수정 외에 어떻게 더 수정할지 자세히 설명하시오.

### 풀이
1. **증명**: 행동 열 $P$가 $b$의 해라는 것은 모든 $s \in b$에 대해 $P$를 실행한 결과가 목표라는 뜻이다(비결정적이면 가능한 모든 결과가 목표). $b' \subseteq b$이면 $b'$의 모든 상태도 $b$에 속하므로 같은 성질을 만족한다. 따라서 $P$는 $b'$의 해이다.
   **상위집합**: 일반적으로 아무것도 보장할 수 없다. $b'' \supseteq b$에 새로 들어온 상태에서 $P$가 실패할 수 있다. 반대 방향으로는 말할 수 있다. $b''$의 해는 반드시 $b$의 해이므로, $b$에 해가 없으면 $b''$에도 해가 없다.
2. **그래프 탐색 수정**: 새로 생성한 신뢰 상태 $b'$를 탐색 집합·프런티어와 비교할 때, 같은지만 보지 말고 포함 관계도 본다.
   - $b'$가 이미 생성된 신뢰 상태 $b$의 **상위집합**이고 $g(b) \le g(b')$이면 $b'$를 버린다. $b'$를 푸는 어떤 해도 $b$를 풀며, $b$가 더 싸게 도달되었기 때문이다.
   - $b'$가 프런티어에 있는 $b$의 **부분집합**이고 $g(b') \le g(b)$이면 $b$를 프런티어에서 지울 수 있다($b'$가 같은 비용 이하로 더 쉬운 문제).
   - 목표 판정과 해 재사용: 해를 아는 신뢰 상태의 부분집합에 도달하면 그 해를 그대로 쓴다.
   - 포함 관계 검사는 비용이 들므로, 상태 집합을 비트 벡터로 표현하면 $b \subseteq b'$를 비트 연산 한 번으로 확인할 수 있다.
3. **AND–OR 탐색 추가 수정**: (b)에 더해 4.5의 메모 표를 신뢰 상태 단위로 확장한다.
   - 성공한 신뢰 상태 $b$의 조건부 계획을 저장하고, 나중에 $b$의 **부분집합**을 만나면 같은 계획(레이블 참조)을 재사용한다.
   - 확정 실패한 $b$를 저장하고, $b$의 **상위집합**을 만나면 즉시 실패로 처리한다.
   - 경로 위 반복 검사도 포함 관계로 확장한다. 현재 신뢰 상태가 경로 위 조상 신뢰 상태의 상위집합이면 진전이 없으므로 그 갈래를 실패로 볼 수 있다(조상보다 더 모르는 상태로 돌아온 것이므로).

## 4.9
### 번역
[교재: multivalued-sensorless-page]에서는 어떤 행동이 주어진 신뢰 상태 안의 어느 물리 상태에서 실행되든 비용이 같다고 가정했다. (이 가정 덕분에 단계 비용이 잘 정의된 신뢰 상태 탐색 문제가 된다.) 이제 이 가정이 성립하지 않을 때 어떤 일이 생기는지 생각해 보자. 이런 맥락에서도 최적성 개념이 여전히 의미가 있는가, 아니면 수정이 필요한가? 또 신뢰 상태에서 행동을 실행하는 “비용”을 여러 방식으로 정의하는 것도 생각해 보자. 예를 들어 물리적 비용들의 최솟값, 최댓값, 최솟값을 하한·최댓값을 상한으로 하는 비용 구간, 또는 그 행동의 가능한 모든 비용의 집합을 그대로 유지하는 방식이 있다. 각각에 대해 A*가 (필요하면 수정을 거쳐) 최적 해를 반환할 수 있는지 탐구하시오.

### 풀이
**최적성의 의미**: 실제 물리 상태를 모르므로 한 계획의 비용이 하나의 수가 아니라 **실제 초기 상태에 따라 달라지는 값**이 된다. 따라서 “최적”을 다시 정의해야 한다. 대표적인 정의는 **최악의 경우 비용**(모든 가능한 초기 상태 중 최대 비용)을 최소화하는 것이고, 확률을 안다면 **기대 비용**을 최소화하는 것이다.

**각 비용 정의에 대한 검토**
- **최솟값**: 각 단계에 가장 낙관적인 비용을 쓴다. 이렇게 얻은 경로 비용은 어떤 실제 궤적의 비용보다도 작거나 같으므로 *하한*이다. A*는 이 낙관적 비용이 최소인 계획을 찾을 뿐, 최악의 경우나 기대 비용 기준으로 최적이라는 보장이 없다.
- **최댓값**: 각 단계의 최대 비용을 더하면, 단계마다 최댓값을 내는 물리 상태가 서로 다를 수 있으므로 실제 최악의 궤적 비용보다 클 수 있다(*상한*). A*는 이 상한을 최소화하는 계획을 찾지만, 진짜 최악 비용 기준의 최적과 다를 수 있다.
- **구간 [최소, 최대]**: 하한으로 탐색 순서를 정하고 상한으로 가지치기하는 분기 한정(branch and bound)에 쓸 수 있다. 하지만 구간은 위의 두 문제를 그대로 가진다. 최적을 판단하기에 정보가 부족하다.
- **가능한 비용 전체를 유지**: 가장 정확한 방법은 신뢰 상태를 **(물리 상태, 지금까지의 누적 비용) 쌍의 집합**으로 확장하는 것이다. 그러면 계획의 최악 비용은 집합 안 누적 비용의 최댓값으로 정확히 계산된다. 이 확장된 상태에서 “최대 누적 비용”을 $g$로 쓰고, 4.7처럼 $\max_s (\text{누적 비용}_s + h^*(s))$ 형태의 허용 가능한 추정을 쓰면 A*는 최악의 경우 기준 **최적 해를 반환할 수 있다**. 대가로 상태 공간이 훨씬 커진다.

### 풀이
변덕스러운 세계에서 Suck은 더러운 칸에서는 그 칸을 청소하고 가끔 이웃 칸도 청소하며, **깨끗한 칸에서는 가끔 먼지를 떨어뜨린다**. 이동은 결정적이다.

**도달 가능한 신뢰 상태** (프로그램으로 계산한 결과, 3개뿐)

```text
           Suck (자기 자신으로)
              ┌───┐
              ▼   │
        {1,2,3,4,5,6,7,8}
          │L          │R
          ▼           ▼
   {1,3,5,7} ◄──L── {2,4,6,8}
     ↺ L, Suck  ──R──►  ↺ R, Suck
```

- $\{1..8\}$ —Left→ $\{1,3,5,7\}$, —Right→ $\{2,4,6,8\}$, —Suck→ $\{1..8\}$
- $\{1,3,5,7\}$ —Left→ 자기 자신, —Suck→ 자기 자신, —Right→ $\{2,4,6,8\}$
- $\{2,4,6,8\}$ —Right→ 자기 자신, —Suck→ 자기 자신, —Left→ $\{1,3,5,7\}$

**풀 수 없는 이유**: 목표는 신뢰 상태가 $\{7,8\}$의 부분집합이 되는 것이다. 그런데 Suck은 현재 칸이 더러운 상태는 깨끗하게 만들지만, 현재 칸이 *이미 깨끗한* 상태에서는 먼지를 떨어뜨릴 수 있다. 센서가 없으니 현재 칸이 깨끗한 가능성을 배제할 수 없고, 따라서 Suck을 할 때마다 “더러운 상태”가 신뢰 상태에 다시 들어온다. 예를 들어 $\{1,3,5,7\}$에서 Suck하면 1→{5,7}, 3→{7}, 5→{5,1}, 7→{7,3}이 되어 다시 $\{1,3,5,7\}$이다. 어떤 행동 열도 신뢰 상태를 $\{7,8\}$ 안으로 줄이지 못하므로 해가 없다.

```text
   {1,3,5,7}  ──Right──►  {2,4,6,8}
              ◄──Left───
```

[연습문제 3.9]의 길 찾기 문제를 다음과 같은 환경으로 바꿀 수 있다.
- 지각은 에이전트를 기준으로 한, 보이는 꼭짓점들의 상대 위치 목록이다. 지각에는 로봇의 위치가 *포함되지 않는다*! 로봇은 지도를 보고 자기 위치를 알아내야 한다. 일단은 각 위치마다 “보이는 모습”이 서로 다르다고 가정해도 좋다.
- 각 행동은 따라갈 직선 경로를 나타내는 벡터이다. 경로가 막혀 있지 않으면 행동은 성공하고, 막혀 있으면 로봇은 경로가 처음으로 장애물과 만나는 지점에서 멈춘다. 에이전트가 0 벡터를 내고 목표(고정되어 있고 알려져 있음)에 있으면, 환경은 에이전트를 (장애물 내부가 아닌) 무작위 위치로 순간이동시킨다.
- 성능 척도는 이동한 거리 1단위마다 1점을 차감하고, 목표에 도달할 때마다 1000점을 준다.
1. 이 환경과 이를 위한 문제 해결 에이전트를 구현하시오. 순간이동할 때마다 에이전트는 새 문제를 정식화해야 하며, 여기에는 현재 위치를 알아내는 일이 포함된다.
2. (에이전트가 움직이면서 적절한 설명을 출력하게 하여) 에이전트의 성능을 기록하고, 100번의 에피소드에 걸친 성능을 보고하시오.
3. 30%의 확률로 에이전트가 의도하지 않은 목적지(보이는 다른 꼭짓점이 있으면 그중 무작위로, 없으면 전혀 움직이지 않음)에 도착하도록 환경을 수정하시오. 이는 실제 로봇의 이동 오차를 거칠게 모형화한 것이다. 그런 오류가 감지되면 에이전트가 현재 위치를 알아내고, 원래 있던 곳으로 돌아가는 계획을 세운 뒤 이전 계획을 이어 가도록 수정하시오. 원래 자리로 돌아가는 것도 실패할 수 있다는 점을 기억하라! 에이전트가 연속된 두 번의 이동 오류를 극복하고도 목표에 도달하는 예를 보이시오.
4. 이제 오류 후 두 가지 다른 복구 방식을 시도하시오. (1) 원래 경로에서 가장 가까운 꼭짓점으로 향하기, (2) 새 위치에서 목표까지 경로를 다시 계획하기. 세 가지 복구 방식의 성능을 비교하시오. 탐색 비용을 포함하면 비교 결과가 달라지겠는가?
5. 이제 보이는 모습이 똑같은 위치들이 있다고 하자. (예를 들어 세계가 정사각형 장애물이 있는 격자라고 하자.) 이제 에이전트는 어떤 종류의 문제에 직면하는가? 해는 어떤 모습인가?

### 풀이
**1. 구현의 뼈대**
- 환경: 다각형 장애물 목록, 목표점. `percept()`는 현재 위치에서 보이는 꼭짓점들의 상대 벡터 목록을 돌려주고, `execute(v)`는 선분이 장애물과 처음 만나는 점에서 멈추게 한다(선분–다각형 교차 계산).
- 에이전트:
  1. **위치 추정**: 지도의 모든 후보 위치(꼭짓점들) 중, 그 위치에서 보이는 꼭짓점의 상대 위치 집합이 지각과 일치하는 곳을 찾는다. “각 위치의 모습이 다르다”는 가정 덕분에 하나로 정해진다. 순간이동 직후는 꼭짓점 위가 아닐 수 있으므로, 지각된 상대 벡터들과 지도 꼭짓점들을 맞추는 평행이동을 찾는 방식으로 구현한다.
  2. **계획**: 3.9처럼 가시성 그래프에서 직선 거리 휴리스틱으로 A* 탐색.
  3. **실행**: 계획의 벡터를 하나씩 내보내고, 목표에 도착하면 0 벡터를 내보낸다.

**2. 성능 기록**: 에피소드마다 “현재 위치 추정 → 계획 경로와 길이 → 실행” 과정을 출력하고, 100 에피소드의 총점(1000 × 도달 횟수 − 총 이동 거리)과 평균 경로 길이를 보고한다. 이동 오차가 없으면 매 에피소드가 최적 경로로 끝나므로 에피소드당 점수는 $1000 - (\text{최단 경로 길이})$이다.

**3. 이동 오류와 복구**
- 오류 감지: 행동 후 지각이 계획상 도착했어야 할 위치의 모습과 다르면 오류다.
- 복구: 위치를 다시 추정하고, 현재 위치에서 “원래 있어야 했던 꼭짓점”까지 A*로 짧은 계획을 세워 실행한 뒤 남은 원래 계획을 이어 간다. 이 복구 계획 실행 중에도 오류가 나면 같은 절차를 재귀적으로 반복한다(복구 대상은 여전히 원래 계획의 그 꼭짓점).
- 시연: 난수 시드를 고정해 두 번 연속 오류가 나는 실행을 찾아, 오류 → 재추정 → 복구 → 다시 오류 → 재추정 → 복구 → 목표 도달 로그를 보이면 된다.

**4. 세 복구 방식 비교**
- (원래) 원래 위치로 돌아가기: 오류 후 되돌아가는 거리가 낭비되기 쉽다.
- (1) 원래 경로에서 가장 가까운 꼭짓점으로: 되돌아가는 거리를 줄이지만, 그 꼭짓점이 목표 쪽으로 더 나아간 지점이 아닐 수 있다.
- (2) 목표까지 다시 계획: 이동 거리 면에서 항상 가장 좋거나 같다(현재 위치에서의 최단 경로이므로).
- **탐색 비용 포함 시**: 재계획(2)은 오류마다 전체 A*를 다시 돌리므로 계산량이 가장 크다. 장애물이 많고 오류가 잦으면 계산 비용 때문에 (1)이 더 나은 절충이 될 수 있다. 이동 거리 1단위와 계산 시간의 교환 비율을 정해 비교해야 한다.

**5. 똑같은 모습의 위치가 있을 때**: 지각만으로 위치를 하나로 정할 수 없으므로 **부분 관측 문제**가 된다. 에이전트는 가능한 위치들의 집합(신뢰 상태)을 유지해야 하고, 해는 단순한 행동 열이 아니라 **조건부 계획**이다. “이 방향으로 움직여 보고, 보이는 모습이 A면 이 계획, B면 저 계획”처럼, 위치를 구분해 주는 정보 수집 이동(위치 파악, localization)이 포함된다.

## 4.13
### 번역
에이전트가 [그림: maze-3x3-figure]과 같은 $3 \times 3$ 미로 환경에 있다고 하자. 에이전트는 자신의 초기 위치가 (1,1)이고, 목표가 (3,3)에 있으며, Up, Down, Left, Right 행동이 벽에 막히지 않는 한 일반적인 효과를 낸다는 것을 안다. 에이전트는 내부 벽이 어디에 있는지 *모른다*. 어떤 상태에서든 에이전트는 가능한 행동들의 집합을 지각하며, 그 상태가 이전에 방문한 상태인지도 알 수 있다.
1. 이 온라인 탐색 문제를, 초기 신뢰 상태가 가능한 모든 환경 구성을 포함하는 신뢰 상태 공간에서의 오프라인 탐색으로 볼 수 있는 이유를 설명하시오. 초기 신뢰 상태는 얼마나 큰가? 신뢰 상태 공간은 얼마나 큰가?
2. 초기 상태에서 서로 다른 지각은 몇 가지가 가능한가?
3. 이 문제에 대한 조건부 계획의 처음 몇 가지 갈래를 기술하시오. 전체 계획은 (대략) 얼마나 큰가?

이 조건부 계획은 주어진 설명에 맞는 *가능한 모든 환경*에 대한 해라는 점에 주목하라. 따라서 알려지지 않은 환경에서도 탐색과 실행을 번갈아 하는 것이 엄밀히 꼭 필요하지는 않다.

### 풀이
1. **오프라인 탐색으로 보기**: 물리 상태를 (에이전트 위치, 벽 배치)로 정의하면, 벽 배치를 모르는 것은 “어떤 물리 상태인지 모르는” 부분 관측 문제가 된다. 행동은 결정적이고, 지각(가능한 행동 집합)은 현재 칸 주변의 벽을 알려 준다. 따라서 가능한 모든 벽 배치를 담은 신뢰 상태에서 시작해, 지각에 따라 일관된 배치만 남기는 AND–OR 탐색을 미리(오프라인으로) 할 수 있다.
   - 내부 벽이 올 수 있는 자리: 이웃한 칸 사이의 경계 $3\times2 + 2\times3 = 12$곳. 각 자리에 벽이 있거나 없으므로 **$2^{12} = 4096$가지** 배치. 위치는 (1,1)로 알려져 있으므로 초기 신뢰 상태의 크기는 4096이다. (목표에 도달 가능한 배치만 세면 1135가지, 모든 칸이 연결된 배치는 431가지 — 프로그램으로 셈.)
   - 신뢰 상태 공간: 신뢰 상태는 (위치, 가능한 배치들의 부분집합)이므로 이론적 상한은 $9 \times 2^{4096}$이다. 실제로 도달 가능한 신뢰 상태는 “지금까지 관찰한 벽 정보와 일치하는 배치 집합”뿐이라 훨씬 적다. 관찰 가능한 벽 자리 12곳 각각이 미관찰/있음/없음이므로 대략 $9 \times 3^{12} \approx 4.8\times10^6$ 이하다.
2. (1,1)은 모서리라 가능한 이동은 Up과 Right 두 방향뿐이고(바깥 벽은 항상 막힘), 각각 내부 벽으로 막혔는지 아닌지에 따라 **4가지** 지각이 가능하다(둘 다 열림, Up만, Right만, 둘 다 막힘). 처음 방문이라는 정보는 항상 같다. 둘 다 막힌 경우는 목표에 갈 수 없는 배치다.
3. **조건부 계획의 처음 갈래 예시**
   ```text
   if 지각 = {Up, Right} then
       Right; if 지각(2,1) = … then …          // 오른쪽 아래 경로부터 시도
   else if 지각 = {Right} then
       Right; …
   else if 지각 = {Up} then
       Up; …
   else 실패                                  // (1,1)이 갇힘
   ```
   각 칸에서 지각은 들어온 방향을 뺀 최대 3방향의 열림/막힘 조합이라 최대 $2^3 = 8$갈래로 나뉜다. 9칸을 탐사하는 동안 막다른 길에서 되돌아오는 이동까지 포함하면 계획의 깊이는 수십 단계가 될 수 있다. 대신 갈래마다 같은 벽 자리를 두 번 관찰하지 않으므로, 전체 계획의 잎 수는 서로 다른 벽 배치 수(목표에 도달 가능한 1135가지)를 넘지 않는다. 즉 노드 수 기준으로 대략 수천~수만 개 규모의 계획이다.

## 4.14
### 번역
에이전트가 [그림: maze-3x3-figure]과 같은 $3 \times 3$ 미로 환경에 있다고 하자. 에이전트는 자신의 초기 위치가 (3,3)이고, 목표가 (1,1)에 있으며, 네 가지 행동 *Up*, *Down*, *Left*, *Right*가 벽에 막히지 않는 한 일반적인 효과를 낸다는 것을 안다. 에이전트는 내부 벽이 어디에 있는지 *모른다*. 어떤 상태에서든 에이전트는 가능한 행동들의 집합을 지각하며, 그 상태가 이전에 방문한 상태인지 새로운 상태인지도 알 수 있다.
1. 이 온라인 탐색 문제를, 초기 신뢰 상태가 가능한 모든 환경 구성을 포함하는 신뢰 상태 공간에서의 오프라인 탐색으로 볼 수 있는 이유를 설명하시오. 초기 신뢰 상태는 얼마나 큰가? 신뢰 상태 공간은 얼마나 큰가?
2. 초기 상태에서 서로 다른 지각은 몇 가지가 가능한가?
3. 이 문제에 대한 조건부 계획의 처음 몇 가지 갈래를 기술하시오. 전체 계획은 (대략) 얼마나 큰가?

이 조건부 계획은 주어진 설명에 맞는 *가능한 모든 환경*에 대한 해라는 점에 주목하라. 따라서 알려지지 않은 환경에서도 탐색과 실행을 번갈아 하는 것이 엄밀히 꼭 필요하지는 않다.

### 풀이
시작과 목표가 4.13과 바뀌었을 뿐 구조는 같으므로 답도 대칭적이다.

1. 물리 상태 = (위치, 벽 배치). 내부 벽 자리 12곳이므로 초기 신뢰 상태는 **$2^{12} = 4096$가지** 배치(위치는 (3,3)으로 알려짐). 목표에 도달 가능한 배치는 4.13과 같은 1135가지다(연결성은 대칭). 신뢰 상태 공간의 이론적 상한은 $9\times2^{4096}$, 실제로 도달 가능한 것은 관찰 정보 조합 수준인 $9\times3^{12}$ 이하.
2. (3,3)도 모서리라 가능한 이동은 Down과 Left 두 방향뿐이다. 각각 막혔는지에 따라 **4가지** 지각이 가능하다.
3. 처음 갈래 예시:
   ```text
   if 지각 = {Down, Left} then Left; …       // 위쪽 줄을 따라 (1,3) 방향부터
   else if 지각 = {Left} then Left; …
   else if 지각 = {Down} then Down; …
   else 실패
   ```
   크기는 4.13과 같은 규모(칸마다 최대 8갈래, 잎 수는 도달 가능한 배치 수 1135 이하)이다. 참고로 그림의 실제 미로에서는 (3,3)의 왼쪽에 벽이 있어 지각은 {Down}이고, 에이전트는 Down으로 (3,2), (3,1)을 거쳐 아래쪽 줄을 따라 (1,1)로 가는 갈래를 따라가게 된다.

### 번역

3. 다음에 갈 곳을 정할 때 깊이 1 탐색을 하는 대신 깊이 $k$ 탐색을 하도록 언덕 오르기 알고리즘을 수정하시오. 가장 좋은 $k$단계 경로를 찾아 그 경로를 따라 한 단계만 움직이고, 이 과정을 반복해야 한다.
4. 새 알고리즘이 지역 최솟값에서 반드시 벗어남을 보장하는 $k$가 있는가?
5. 이 경우 LRTA*가 어떻게 에이전트를 지역 최솟값에서 벗어나게 하는지 설명하시오.

### 풀이
※ 원문의 “path-planning-agent-exercise”는 이 문제집의 4.12를 가리킨다(원본 사이트 링크는 4.11로 잘못 연결됨). 문제의 그림은 원본 저장소에 없어서 3.9의 볼록 다각형 장애물 장면으로 생각하면 된다.

1. **언덕 오르기 길 찾기**: 현재 위치에서 보이는 꼭짓점 중 목표까지 직선 거리가 가장 작은 곳으로 이동하고, 현재 위치보다 가까운 꼭짓점이 없으면 멈춘다. 장애물 배치에 따라 **갇힐 수 있고, 볼록 장애물만 있어도 가능하다.** 예: 목표 바로 앞을 길고 얇은 볼록 장애물(긴 막대)이 가로막고 있고, 에이전트가 그 막대 중앙 바로 뒤에 있다고 하자. 에이전트에서 목표까지는 막대 두께 정도로 가깝지만, 보이는 꼭짓점(막대의 양 끝)은 목표에서 막대 길이의 절반 이상 떨어져 있다. 더 가까운 꼭짓점이 보이지 않으므로 그 자리가 지역 최솟값이다. 다만 순간이동 직후가 아니라 꼭짓점 위에서 출발하는 경우에는, 볼록 장애물만으로는 이런 상황이 생기기 어렵다(꼭짓점에서는 같은 장애물을 따라 목표 쪽으로 이어지는 꼭짓점이 보이기 때문).
2. **갇히는 비볼록 환경**: 목표를 향해 등을 돌린 **U자(또는 C자) 모양** 장애물을 만들고, 에이전트를 U자 안쪽 깊숙이 둔다. 즉 U자의 바닥이 에이전트와 목표 사이에 있고 입구는 목표 반대쪽이다. U자 안에서 보이는 꼭짓점은 모두 안쪽 벽의 꼭짓점이고, 그중 목표에 가장 가까운 것은 바닥 쪽 꼭짓점이다. 그 지점에 도달하면 보이는 어떤 꼭짓점도 목표에 더 가깝지 않으므로, 꼭짓점 위에서 출발해도 지역 최솟값에 갇힌다. 빠져나가려면 목표에서 멀어지는 U자 입구 쪽으로 돌아가야 한다.
3. **깊이 $k$ 언덕 오르기**:
   ```text
   loop:
       if 목표가 보이면 목표로 이동하고 종료
       P ← 현재 위치에서 시작하는 모든 k단계 꼭짓점 경로 중
           (경로 길이 + 끝점에서 목표까지 직선 거리)가 가장 작은 것
       P의 첫 단계로 이동
   ```
4. **보장되는 $k$가 있다.** 꼭짓점이 $V$개면 어떤 꼭짓점에서든 목표까지의 최단 경로는 많아야 $V$단계이므로 $k \ge V$이면 최단 경로 전체를 내다볼 수 있어 지역 최솟값이 없다. 다만 이는 사실상 전체 탐색이고, 실용적으로는 장애물 “함정”의 깊이(빠져나오는 데 필요한 단계 수)보다 큰 $k$면 충분하다. 고정된 작은 $k$로는 그보다 깊은 함정을 만들 수 있으므로 일반적인 보장은 없다.
5. **LRTA\***: 각 꼭짓점의 추정 비용 $H(s)$를 학습한다. 처음 $H$는 직선 거리이고, 꼭짓점 $s$에서 움직일 때마다 $H(s) \leftarrow \min_{s'} [c(s,s') + H(s')]$로 갱신한다. U자 바닥에 갇히면 그 지점의 $H$ 값이 이웃을 거치는 비용만큼 올라가고, 다시 돌아오면 또 올라간다. 이렇게 함정 안 꼭짓점들의 $H$가 계속 커지다 보면 결국 U자 입구 쪽 경로가 더 싸 보이게 되어 에이전트가 빠져나온다. 즉 “함정을 메워 평평하게 만드는” 효과로 지역 최솟값을 탈출하며, 유한한 공간에서는 목표에 반드시 도달한다.

## 4.16
### 번역
DFS와 마찬가지로, 온라인 DFS는 무한 경로가 있는 가역적 상태 공간에서 완전하지 않다. 예를 들어 상태는 무한한 2차원 격자의 점이고, 행동은 단위 벡터 $(1,0)$, $(0,1)$, $(-1,0)$, $(0,-1)$이며 이 순서로 시도한다고 하자. $(0,0)$에서 시작한 온라인 DFS가 $(1,-1)$에 도달하지 못함을 보이시오. 에이전트가 현재 상태뿐 아니라 모든 후속 상태와 그곳으로 가는 행동도 관찰할 수 있다고 하자. 무한 경로가 있는 양방향 상태 공간에서도 완전한 알고리즘을 작성하시오. 그 알고리즘은 $(1,-1)$에 도달하는 동안 어떤 상태들을 방문하는가?

### 풀이
**온라인 DFS가 도달하지 못하는 이유**: 온라인 DFS는 각 상태에서 아직 시도하지 않은 행동 중 첫 번째를 시도하고, 새 상태에 도착하면 그 상태에서 다시 첫 행동부터 시도한다. $(0,0)$에서 첫 행동 $(1,0)$으로 $(1,0)$에 가고, 거기서도 $(1,0)$으로 $(2,0)$, 다시 $(3,0)$, … 로 오른쪽으로 끝없이 간다. 매번 새 상태이므로 되돌아오는(backtrack) 일이 생기지 않는다. 따라서 $x$ 좌표가 계속 증가하고 $y = 0$인 상태만 방문하며, $(1,-1)$은 영원히 방문하지 않는다.

**완전한 알고리즘 (온라인 반복 심화)**: 가역적이므로 언제든 왔던 길로 되돌아갈 수 있다. 깊이 한계 $L = 1, 2, 3, \dots$에 대해, 시작점에서 깊이 $L$까지 DFS로 탐사하고 매번 시작점으로 되돌아온다. 후속 상태를 관찰할 수 있으므로, 어느 상태에서든 **후속자 중에 목표가 보이면 바로 그리로 이동**한다.

```text
function ONLINE-ID(start):
    for L = 1, 2, 3, …:
        if DLS(start, L) then return success
function DLS(s, L):
    if 목표 ∈ 관찰된 후속자(s) then 그 행동을 실행; return true
    if L = 0 then return false
    for each 행동 a (순서대로), 결과 s′가 현재 경로에 없으면:
        a를 실행; if DLS(s′, L−1) then return true
        a의 역행동을 실행하여 s로 복귀
    return false
```
깊이 $L$ 안의 모든 상태를 유한 시간에 방문하므로, 목표가 유한한 거리에 있으면 반드시 찾는다(완전).

**$(1,-1)$에 도달하는 동안 방문하는 상태**: $L=1$에서 $(0,0)$의 후속자는 $(1,0), (0,1), (-1,0), (0,-1)$이고 목표가 아니다. 첫 행동 $(1,0)$으로 $(1,0)$에 가면 그곳의 후속자 $(2,0), (1,1), (0,0), (1,-1)$ 중에 목표 $(1,-1)$이 보이므로 바로 이동한다.

방문한 상태: **$(0,0) \to (1,0) \to (1,-1)$**.

## 4.17
### 번역
LRTA*의 시간 복잡도를 공간 복잡도와 관련지어 설명하시오.

### 풀이
- **공간**: LRTA*는 방문한 상태마다 추정 비용 $H(s)$와 (s, a) → 결과 표를 저장한다. 따라서 공간은 **지금까지 방문한 서로 다른 상태 수** $m$에 비례한다, $O(m)$ (분기 계수까지 치면 $O(mb)$).
- **시간과의 관계**:
  - 에이전트는 한 단계에 상태를 하나만 새로 방문할 수 있으므로, 공간은 실행 단계 수(시간)를 넘지 않는다. **공간 ≤ 시간**.
  - 반대로 같은 상태를 여러 번 오가며 $H$를 갱신하므로 시간은 공간보다 훨씬 클 수 있다. 상태가 $n$개인 유한 공간에서 LRTA*는 최악의 경우 $O(n^2)$단계 안에 목표에 도달한다는 것이 알려져 있다. 즉 저장하는 상태가 $m \le n$개라면 시간은 최악 $O(m^2)$, **시간은 공간의 제곱 수준**까지 커질 수 있다.
- 정리: LRTA*는 방문한 상태에 대해서만 메모리를 쓰는 대신, 지역 최솟값을 “메우기” 위해 같은 상태를 반복 방문하는 시간으로 그 대가를 치른다.
